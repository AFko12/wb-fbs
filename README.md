# Скорость доставки FBS — Wildberries

Дашборд по этапам пути FBS-заказа: как быстро мы сдаём товар на СЦ, сколько СЦ
его держит у себя и сколько идёт дорога до пункта выдачи. Открыт по адресу
https://afko12.github.io/wb-fbs/ и обновляется сам.

## Контрольные точки

| | Точка | Откуда берём | Точность |
|---|---|---|---|
| T0 | заказ создан | `createdAt`, `/api/v3/orders` | точно |
| T1 | скан ШК ТТН на СЦ | `scanDt` поставки, `/api/v3/supplies` | точно |
| T2 | сортировка товара | статус `sorted` | 5 минут |
| T3 | прибытие в ПВЗ | статус `ready_for_pickup` | 5 минут |
| T4 | выдача клиенту | дата продажи, `/supplier/sales` | точно |

Этапы на дашборде: **приёмка** T0→T1, **обработка на СЦ** T1→T2,
**доставка до ПВЗ** T2→T3, **весь путь** T0→T3.

Время T3→T4 (сколько заказ ждёт клиента в ПВЗ) показано отдельно и в оценку
работы СЦ не входит: покупатель может забирать заказ неделями, и включать это
время в скорость доставки нельзя.

WB не отдаёт моменты T2 и T3 — только текущий статус задания. Поэтому статусы
опрашиваются каждые 5 минут, и метка ставится в момент, когда статус сменился.
Этапы 2 и 3 заполняются только для заказов, оформленных после запуска опроса;
приёмка считается по точным датам WB и доступна за весь период.

## Файлы

| Файл | Что делает |
|---|---|
| `index.html` | Сам дашборд, одна самодостаточная страница с вшитыми данными |
| `fetch_wb_data.py` | Сборщик: заказы и продажи из Statistics API, точки T0/T1 и СЦ приёмки из Marketplace API |
| `poll_status.py` | Опрос статусов каждые 5 минут: ставит метки T2 и T3 |
| `merge_cache.py` | Слияние кэшей, когда сборщик и опрос пишут в репозиторий одновременно |
| `wb_cache.json` | Накопленное состояние: заказы, продажи, метки этапов, курсоры |
| `data.json` | Готовые данные для страницы (пересобираются из кэша) |

## Автообновление

| Что | Когда | Через что |
|---|---|---|
| Заказы, продажи, приёмка | 03:30 и 14:00 МСК | `.github/workflows/update.yml` |
| Статусы (сортировка, ПВЗ) | круглосуточно, шаг 5 минут | `.github/workflows/poll.yml` |

Токен лежит в секрете репозитория `WB_TOKEN` (Settings → Secrets and variables
→ Actions). Нужны обе категории доступа: «Статистика» и «Маркетплейс».

Запустить руками: вкладка **Actions** → нужный процесс → **Run workflow**.
У сборщика есть два переключателя: *перечитать все заказы заново* и *быстрый
режим* (не ждать занятый общий лимит статистики WB).

## Про лимиты WB

Statistics API даёт кабинету один запрос в минуту, и лимит общий на все сервисы
аналитики продавца — соседний сервис может заблокировать нас на часы. Поэтому
сборщик работает инкрементально (помнит курсор и просит только изменения) и за
запуск гарантированно делает один запрос — к тому источнику, что сильнее устарел.
Опрос статусов ходит только в Marketplace API, у которого лимиты свои и щадящие,
поэтому он не мешает сборщику и не рискует блокировкой.

## Запуск руками

```bash
WB_TOKEN="..." python3 fetch_wb_data.py --inject index.html   # обновить данные
WB_TOKEN="..." python3 poll_status.py --once                  # один проход опроса
python3 fetch_wb_data.py --rebuild --inject index.html        # пересобрать страницу без API
```
